#### Лабораторная 6

- **Цель работы**: Завершение интерфейса `пользователя` в `React`
- **Порядок показа**:
  - **Скриншоты 1-2** Показать сначала две страницы фронтенда с `mock` без запущенного сервиса.
  - **Скриншоты 3-6** Затем показать 4 страницы фронтенда с бэкендом,
  - **Скриншоты 7-8** внести изменения в БД, показать их во фронтенде.
  - **Скриншоты 9** Показать авторизацию, обновить страницу по `F5` в состояние гостя `Redux` а в `Application` показать что `JWT`/`сессия в cookie` остались.
  - **Скриншоты 10** Затем использовать содержимое `localStorage`/`cookie` из вкладки `Application` чтобы показать плитку услуг пользователя в `insomnia`/`postman` с признаком для удаления.
  - **Скриншоты 11-12** Показать в коде все состояния `redux` и показать `axios` в кодогенерации.
  - **Скриншоты 13-14** Показать применение сгенерированного кода фронтенда из `swagger` в `thunk` и что они названы по теме.
  - **Скриншоты 15-16** Показать в `network` адрес `AJAX` через `proxy`, названия и адреса из `Silo(MinIO)` для изображений.
- **Контрольные вопросы**: схема redux-toolkit (reducer, store, middleware), axios, local storage. CORS и обратный прокси, BFF и GraphQL, Next.js и SSG, FSD
- **Диаграммы**: диаграмма прецедентов интерфейса `React`.
- **Задание**: Внедрить менеджер состояний для хранения значений фильтров, добавить авторизацию и возможность создания `услуг` через `Redux Toolkit` `redux-thunk`, кодогенерация взаимодействия с `API` через `Axios`

Содержимое карточек получать из вашего веб-сервиса. Ограничение с `CORS` решить через проксирование `React` (для `S3` тоже добавить второй маршрут). В методах `ajax` предусмотреть получение данных из коллекции с `mock`-объектами при отсутствии доступа к вашему бэкенду (только как `гость`). Фильтры (по дате, названию или цене в зависимости от вашей темы как в 1 и 3 лабораторных) также добавлять в запрос к бэкенду. Добавить страницу `Добавления` услуги, кнопки `удаления` и `лайков` на соответствующих страницах.

Добавить страницу для авторизации. Добавление в `Redux Toolkit` состояния интерфейса после авторизации. В приложении должно быть реализовано переключение между интерфейсом гостя и интерфейсом пользователя по кнопке `Вход`/`Выход`. После авторизации в меню должно отображаться `Выход`. При выходе должен сбрасываться фильтр пользователя. Добавление менеджера состояний `Redux Toolkit` для хранения фильтра услуг. Рекомендуется использовать расширение для браузера [redux-devtools](https://chromewebstore.google.com/detail/redux-devtools/lmhkpmbekcpmknklioeibfkpmmfibljd). 

Для обращений к методам веб-сервиса доменов `услуг` использовать `axios`, кодогенерацию и `redux-thunk middleware`. При выполнении запросов отображать на странице анимацию, блокирующую кнопки пользователя. Для запросов  `авторизации`/`деавторизации` только `axios`, вручную передавать состояние в Redux без кодогенерации и `thunk`.
