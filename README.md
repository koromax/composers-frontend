## Режимы данных

Один и тот же код поддерживает API и демонстрационный mock-режим:

- `npm run dev` запускает локальную разработку в режиме API. Запросы `/api` и `/s3` проксируются настройками из `vite.config.ts`.
- `npm run dev:mock` запускает локально mock-данные без запросов чтения к API.
- `npm run build` собирает приложение в режиме API.
- `npm run build:mock` собирает приложение в режиме mock — используйте эту сборку для GitHub Pages, где бэкенда нет.

Режим задаётся в `.env.api` или `.env.mock`. Mock-сборка позволяет просматривать и фильтровать демонстрационные данные; авторизация и изменение данных в ней недоступны.

## Развертывание на GitHub Pages

Для публикации выполните `npm run deploy`. Команда собирает mock-версию с базовым путём `/composers-frontend/`, manifest и Service Worker, а затем публикует содержимое `dist` в ветку `gh-pages`.

Роутер использует Vite `BASE_URL` как `basename`; ссылки внутри приложения учитывают путь проекта. Файл `404.html` — fallback GitHub Pages для открытия и перезагрузки вложенных маршрутов.

PWA регистрирует Service Worker с автоматическим обновлением и precache собранных файлов, включая демонстрационное видео. После публикации проверьте manifest и активный Service Worker во вкладке Application браузерных DevTools, установите приложение и проверьте его повторное открытие без сети.
